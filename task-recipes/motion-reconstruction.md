# Reconstruct and verify motion

Preserve or repair supplied animation and interactive behavior using an explicit sequence and observed full-cycle verification.

Read [the shared portable recipe contract](README.md) first. Use the authoritative expansion and recommended lenses in [catalog.json](catalog.json); adapt them to the current task and actual tools.

## Extract a sequence, not one frame

Inspect supplied markup and JavaScript and observe the actual source behavior where available. Preserve its logic when requested. Describe initial state, timed events, transitions, complete cycle, looping/reset, user controls and tab synchronization. Distinguish decorative illustrations from measured live product metrics.

Keep approved visual structure fixed while diagnosing jumps, flashing, imperceptible changes, speed mismatches or misplaced controls. Compare sibling timing deliberately; do not replace meaningful product behavior with arbitrary floating decoration. Use the real component and state owner.

## Verify over time

Observe at least one complete cycle and each changed interaction after implementation. Check layout stability, pause/restart/speed controls when present, tab activation, visibility changes, cleanup and reduced-motion behavior. Capture a time-indexed observation or recording plus relevant screenshots; a still image alone is not animation evidence.

Verify the final packaged runtime preserves scripts/assets and does not reset unexpectedly. Report the controls/states and time span actually observed. If runtime tools are unavailable, finish independent source work and identify unverified timing instead of asserting smoothness.
