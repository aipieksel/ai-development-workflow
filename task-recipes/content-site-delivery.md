# Deliver a source-grounded content site

Reconcile requested pages and source content, reuse the approved presentation and verify routes, metadata, links and delivered artifacts.

Read [the shared portable recipe contract](README.md) first. Use the authoritative expansion and recommended lenses in [catalog.json](catalog.json); adapt them to the current task and actual tools.

## Reconcile content and presentation owners

Inventory all requested source articles/pages, routes, metadata, media and approved shared sections. Read complete relevant source text before deriving facts or rewriting. Distinguish facts, approved copy, illustrative examples and missing information. Use the actual content/SEO and design-system owner skills instead of introducing a second set of project rules.

Create a source-to-output target map. Preserve optimized headings or other protected copy when requested. Verify destinations against the real route/content inventory; do not invent guides, features, services or product claims. Keep authored content, reusable presentation and SEO/schema files in the receiving project's preferred formats.

## Deliver the full collection

Validate parsers, metadata, slugs, canonical and locale behavior, assets and internal links. Verify structured data agrees with visible content. Render representative page types and every high-risk changed pattern. Add design audit/visual-review operations when presentation is changing; do not omit them because the default content recipe emphasizes content integrity.

Reconcile every requested target, including unchanged or excluded items. Test final navigation, content interactions and authorized destination readback. Report partial source access and unrendered targets accurately, with no invented coverage.
