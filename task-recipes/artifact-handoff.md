# Verify and deliver an artifact

Reconcile final source and package identity, repair in-scope delivery defects and verify the authorized destination with readback.

Read [the shared portable recipe contract](README.md) first. Use the authoritative expansion and recommended lenses in [catalog.json](catalog.json); adapt them to the current task and actual tools.

## Resolve the exact deliverable

Identify the current approved output, source revision, expected files, packaging contract, destination and authorized delivery action. Inspect existing completed work before changing source. For an already valid artifact needing only delivery, shorten the recipe to focused verification and authorized handoff; do not force a rebuild or new plan record.

Trace missing styling, stale files or broken imports to the actual packaged bytes and relative assets. Inventory archive nesting, member paths, fonts/images/CSS/JS and checksums when appropriate. Keep application storage separate from repository publication and respect explicit no-publish boundaries.

## Verify the handoff itself

Open or import the final deliverable through the receiving mechanism when available. Verify standalone sections from their actual extracted location. Use destination/readback evidence tied to the same output identity and version. For generated-image tools, retain their actual result/identity instead of duplicating image downloads solely for packaging evidence.

Report prepared, packaged, saved/uploaded, published and runtime-verified states separately. An upload receipt does not prove rendering, and a local preview does not prove the destination updated. Complete useful independent preparation if delivery access fails, preserve the artifact, and state the exact remaining gap without falsely claiming success.
