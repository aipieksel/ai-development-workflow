# Convert to native editable YAML

Map supplied sources to the receiving kit and real widget capabilities, then validate editable structure, assets and import/render parity.

Read [the shared portable recipe contract](README.md) first. Use the authoritative expansion and recommended lenses in [catalog.json](catalog.json); adapt them to the current task and actual tools.

## Inventory before mapping

Resolve the latest supplied receiving kit, schema, examples, registry, renderer and preset logic before drafting YAML. Read the actual native-YAML and design-system preset owner skills when available. Inspect the complete source page and its font/assets. Record excluded sections and the exact custom-code allowlist from the current request; never generalize one allowed map to unrelated sections.

Examine native card capabilities, content slots, nesting and alignment before assembling custom structures. Map each section to supported widgets and document capability gaps. Use actual product/tab widget APIs and item cardinalities rather than recreating their internal HTML. Reuse available variables and presets with their documented semantics.

## Produce editable output

Build supported native structures, stable identities and responsive fields. Unsupported properties remain explicit; do not silently substitute an HTML widget or delete content to pass validation. Validate parsed data against the actual schema and semantic widget contract. Reconcile requested sections, products, assets and preset references.

When a receiving editor is available, import, inspect, edit, save/reload and compare rendered output and interactions. If only source/schema checks are possible, label them accurately and keep visual/import parity unverified. Deliver the exact final YAML/package with valid relative assets and requested exceptions only.
