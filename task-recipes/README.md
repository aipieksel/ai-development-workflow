# Task recipes

Recipes compose existing operations for recurring task shapes. They are patterns inside the
single main skill, not separate public skills, running agents or additional permissions.
The [catalogue](catalog.json) owns each ordered expansion and recommended specialist lenses.
The [advanced reference](../references/advanced-reference.md#task-recipes) documents all ten.

Read the [workflow contract](../references/workflow-contract.md), selected recipe and actual
operation/profile instructions. Announce scope, phases/owners and the real worker count.
Assess [UI applicability](../references/ui-routing.md); visual outcomes apply the
[UI Design Director](../specialists/ui-design.md) within existing ownership.

## Apply a recipe

1. Recover the current request, corrections, exact source/version and selected record. Use
   [task contracts](../references/task-contracts.md) to identify the transformation mode,
   protected properties, allowed changes, requested targets and delivery boundary.
2. Treat the expansion as a starting pattern. Preserve analysis/plan/review-only, mockup-first
   and no-publish limits. Reuse exact current evidence and continue the same record.
3. Load the relevant operations progressively. Deduplicate equivalent work and satisfy actual
   prerequisites. When borrowing only part of a recipe, identify that subset and its coverage
   rather than claiming the complete recipe ran. Do not compare every unrelated catalogue row.
4. For files/assets without Git, `repo.snapshot` is an honest inventory with relevant identities,
   hashes and observed states. Never invent a repository, commit, runtime or completed check.
5. Use the real receiving system's format, kit, image tool, importer or publishing capability.
   The recipe does not supply a missing browser/editor/tool or expand current permission.
6. Every product/test/docs write needs the current concrete plan, completed criticism and
   visible-briefing admission. Keep one owner for overlapping changes and generation/package
   outputs. Reviewers report findings; admitted executors repair them and repeat affected checks.
7. Bind acceptance to the actual output revision. Schema/structure, rendering, interactions,
   motion and destination readback establish different claims. Preserve failed, pending and
   blocked states rather than counting them as delivery.

An explicit `recipe <id>` follows the main skill prefix, for example:

```text
/ai-development-workflow recipe visual-correction Repair the supplied layout mismatch while preserving approved styling.
```

Auto may choose a relevant recipe from ordinary prose. Selection alone does not allocate a
record, dispatch a worker or execute commands. G/numeric controls keep their advanced
compatibility semantics. Retired native `stage` and `pipeline` selectors are not supported.
