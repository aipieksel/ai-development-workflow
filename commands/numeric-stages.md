# Numeric stages and continuation

Follow the [original workflow](../references/standard-workflow.md) for the selected
numeric mode, `criticize`/`criticise`, `execute`, `revise`/`r` or `resume`.
Only 0 creates a record within explicit legacy numeric controls. The primary `plan` word uses
[public Plan](../references/public-modes.md), including capture and completed criticism. `0123` creates, plans, criticises and executes; `123`
updates the selected record without creating another. Preserve the original
supported stage sequences, order, source capture, scope, critique and readiness rules.

Apply [task routing](../references/task-routing.md): choose a concrete Plan/Build/Review/Loop
mode and actual workers within the requested operations. Stage 0 alone may delegate source
capture/inspection; it still does not invent planning or execution. Writing sequences require
independent plan and result review; unavailable worker tools block dependent work.
Apply the [shared execution rules](../references/command-runtime.md). On an existing
G-selected record, load that preset’s command file as well and reconcile its pending
agent work; never respawn blindly or move delegated stage 3 back to the parent.
Planning-only invocations cannot dispatch implementation or post-implementation agents.
An explicit numeric mode selects operations; reading a preset file does not add stage 0.
The [mandatory workflow contract](../references/workflow-contract.md) adds required
pre-write prerequisites without granting additional product scope.

Require current completed criticism and the public briefing at every execution admission.
For `013`, `13` or `3`, show requested stages separately from missing prerequisites, then
complete the plan/criticism or reuse exact valid evidence before writes. No silent skip or
new approval ceremony. GS retains its assessment requirement. A quick checklist supports
ordinary continuation and `resume` through its compact admission, not development-only stages.
