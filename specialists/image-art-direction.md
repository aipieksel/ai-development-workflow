# Image art direction and consistent asset production

Produce or correct visual assets against a clear composition contract, with consistent product identity and honest fidelity claims.

Read the [shared specialist contract](../references/specialist-contract.md),
[task contracts](../references/task-contracts.md) and
[acceptance evidence](../references/acceptance-evidence.md).
This lens guides the assigned planning, implementation or review stage; it does not supply an image tool or register a new agent.

## Use and exclude

- Use for generated product illustrations, precise image edits, coherent product families, hero/CTA imagery or reference-based visual concepts.
- Combine reference-fidelity for protected composition, design-system for the surrounding page, and artifact-delivery for requested asset sets.
- Exclude exact data charts and technical diagrams that need deterministic geometry or factual labels. Use their appropriate available tools. For PNG-to-SVG implementation and pixel comparisons, use media-library instead.

## Define the visual contract

Inspect the provided reference images before editing. Inventory selected bases, overlays/logos, dimensions, background/transparency, required files and any explicit exceptions. Record what remains fixed: camera angle, chassis geometry, object scale, margins, direction, color treatment or the placement reserved for later branding.

Separate three jobs. A local edit changes named regions while preserving the approved concept. A consistent product set keeps its shared base and varies the specified product elements. Concept exploration creates meaningfully different visual ideas within the approved brand and brief. Do not count a logo or label swap as a new concept when distinct concepts were requested.

For multi-asset work, make a compact target matrix with product/concept, base, permitted variation, dimensions, background and output form. An individual-image request is not satisfied by a contact sheet; a requested sheet needs the stated number of discernible concepts.

## Produce with the actual capabilities

- Use the available image-generation/editing tool when appropriate and authorized, following its host instructions for reference images, transparency and output handling. Inspect local references through the supported image viewer before editing when required.
- Prefer preserving an approved base and placing product elements through a supported compositing/edit capability when that is the requested operation. Do not invent a pixel-lock or compositing API, substitute a prohibited editing tool, or promise deterministic preservation from a generative tool.
- If the actual tool cannot guarantee an exact unchanged base, disclose that concrete boundary and pursue the closest authorized method; do not label it pixel-identical without comparison evidence.
- Specify shared perspective, ground plane, baseline, object scale, overlap and occlusion. Check that overlays face the same direction as the base, rest plausibly on the same surface, and do not expose unintended feet, crop important details or create inconsistent shadows.
- Evaluate texture/material realism, symmetry, small repeated details, logo accuracy and legibility at intended display size. A smooth thumbnail can conceal distorted vents, uneven lights or an implausible globe.
- Make product concepts semantically appropriate. Source current official identity assets when needed under the available retrieval rules; do not invent a brand mark from an initial or reuse one product's mascot for another.
- For HTML hero/CTA use, verify the actual crop, fit, edge blend, reserved copy/logo space and responsive composition in the component. Asset quality alone does not establish integration quality.

## Acceptance evidence

Reconcile all requested assets, dimensions, backgrounds and output forms. Compare affected regions and protected properties against the references; identify residual distortion or uncertainty instead of assigning unsupported perfect scores. Distinct concepts should communicate materially different ideas while remaining within the authorized design space.

Record the actual generated/edited output identity and available tool evidence. Follow the host's generated-image display and persistence rules; do not reconstruct, download or upload an image merely to manufacture local evidence when the host already handles delivery. Report separately any requested downloadable package or page integration that has not been verified.

## Failure modes

Do not regenerate the entire approved base for convenience, add unrequested logos/glows/backgrounds, invert the wrong object, crop away a defect to imply it was repaired, or claim that raster artwork became editable vector geometry. Exactness claims require evidence at the stated dimensions and renderer, not confident prompting.
